# คู่มือนำระบบขึ้นใช้งานจริง

ใช้เวลาประมาณ 1 ชั่วโมง ไม่มีค่าใช้จ่าย ต้องมีบัญชี GitHub (มีแล้ว) และสมัคร Supabase ด้วยอีเมลใดก็ได้

## 1. เปิดหน้าเว็บด้วย GitHub Pages

1. ไปที่ repository `keerazone` บน GitHub > **Settings** > **Pages**
2. Source เลือก **Deploy from a branch** เลือก branch ที่มีไฟล์ระบบ (เช่น `main`) โฟลเดอร์ `/ (root)` > Save
3. รอ 1–2 นาที จะได้ลิงก์ประมาณ `https://cobio123.github.io/keerazone/`

หมายเหตุ: GitHub Pages แบบฟรีต้องเป็น repository สาธารณะ (public) ไฟล์ในระบบนี้ไม่มีข้อมูลลับ — PIN เก็บในฐานข้อมูลแบบเข้ารหัส

ถึงขั้นนี้ระบบใช้งานได้ใน **โหมดสาธิต** แล้ว เหมาะสำหรับนำเสนอที่ประชุม

## 2. สร้างฐานข้อมูล Supabase (ฟรี)

1. สมัครที่ supabase.com > **New project** ตั้งชื่อ เช่น `keerazone` เลือก Region **Southeast Asia (Singapore)**
2. เมนู **SQL Editor** > New query > วางไฟล์ `supabase/schema.sql` ทั้งไฟล์ > **Run**
3. New query อีกครั้ง > วาง `supabase/seed.sql` > **Run** (ร่างรายการกีฬา — แก้ภายหลังได้)

## 3. ใส่ข้อมูลโรงเรียนและรายการกีฬาจริง

- **โรงเรียน:** ทำไฟล์ CSV ตามแม่แบบ `supabase/schools_template.csv` (คอลัมน์ `code,name,district`)
  แล้วไปที่ **Table Editor** > ตาราง `schools` > **Insert** > **Import data from CSV**
- **รายการแข่งขัน:** แก้ในตาราง `sports` และ `events` ได้แบบเดียวกับ Excel ใน Table Editor
  แต่ละกีฬากำหนดรุ่นอายุเองได้ (คอลัมน์ `division`) — ควรให้ฝ่ายเทคนิคกีฬาแต่ละชนิดตรวจก่อนเปิดรับ
- ห้ามแก้ `id` ของรายการหลังโรงเรียนเริ่มแจ้งแล้ว (ความประสงค์ผูกกับ `id`)

## 4. สร้างบัญชีผู้ดูแล 1–3 คน

1. **Authentication** > **Users** > **Add user** > Create new user (ใส่อีเมลและรหัสผ่าน ติ๊ก Auto Confirm)
2. SQL Editor รันคำสั่งนี้ (เปลี่ยนอีเมล):

```sql
insert into public.admins (user_id, email)
select id, email from auth.users where email in ('admin1@example.com', 'admin2@example.com');
```

## 5. เชื่อมหน้าเว็บกับฐานข้อมูล

1. Supabase > **Project Settings** > **API** คัดลอก **Project URL** และ **anon public key**
2. แก้ไฟล์ `assets/js/config.js` ใส่ค่าใน `SUPABASE_URL` และ `SUPABASE_ANON_KEY` แล้ว commit ขึ้น GitHub
3. เปิดเว็บอีกครั้ง แถบสีส้ม "โหมดสาธิต" จะหายไป แปลว่าเชื่อมฐานข้อมูลจริงแล้ว

anon key เปิดเผยได้ตามการออกแบบของ Supabase ความปลอดภัยอยู่ที่ RLS และฟังก์ชันใน `schema.sql`:
ทุกคนอ่านสรุปได้ แต่การบันทึกต้องผ่าน PIN ของโรงเรียนนั้น หรือบัญชีผู้ดูแลเท่านั้น

## 6. ออก PIN และเปิดรับ

1. เข้า `admin.html` ด้วยบัญชีผู้ดูแล
2. ตั้งวันเปิด–ปิดรับตามมติที่ประชุม > บันทึก
3. กด **ออก PIN ให้โรงเรียนที่ยังไม่มี** จะได้ไฟล์ Excel รหัสโรงเรียน + PIN (แสดงครั้งเดียว — เก็บเป็นความลับ)
4. ส่ง PIN ให้แต่ละโรงเรียนทางหนังสือราชการหรือ LINE ส่วนตัวของครูผู้ประสานงาน พร้อมลิงก์ `.../survey.html`

## ข้อควรรู้เรื่องแผนฟรี

| เรื่อง | รายละเอียด | ทางรับมือ |
| --- | --- | --- |
| Supabase หยุดโปรเจกต์ชั่วคราว | ถ้าไม่มีการใช้งาน 7 วัน | ช่วงเปิดรับมีคนใช้ทุกวัน · ถ้าหยุดกด Restore ใน Dashboard ได้ฟรี |
| สำรองข้อมูล | แผนฟรีไม่มีสำรองอัตโนมัติ | กดส่งออก Excel ในหน้าสรุปทุกสัปดาห์ |
| ขนาด | ฐานข้อมูล 500 MB | ข้อมูลความประสงค์ใช้ไม่ถึง 1 MB |

## ปัญหาที่พบบ่อย

- **โรงเรียนลืม PIN:** หน้าผู้ดูแล > ออก PIN ใหม่ > แจ้งโรงเรียน (PIN เดิมใช้ไม่ได้ทันที)
- **โรงเรียนขอแก้หลังปิดรับ:** หน้าผู้ดูแล > แก้แทน
- **หน้าเว็บขึ้น "โหลดข้อมูลไม่สำเร็จ":** ตรวจว่าโปรเจกต์ Supabase ไม่ได้ถูกหยุด และค่าใน `config.js` ถูกต้อง
